# LangGraph Course - ReAct Agent 项目完整拆解

## 📚 项目概述

这是一个基于 **LangGraph** 实现的 **ReAct（Reasoning and Acting）Agent** 教程项目。ReAct 是一种让 AI 代理能够**推理**（Reasoning）和**行动**（Acting）的模式，通过交替进行思考和工具调用来完成任务。

### 核心特点
- ✅ **ReAct 模式**：推理 → 行动 → 推理的循环
- ✅ **工具集成**：支持多种工具（搜索、计算等）
- ✅ **图工作流**：使用 LangGraph 管理复杂的控制流
- ✅ **状态管理**：使用 MessagesState 跟踪对话历史

## 🔍 核心文件详细拆解

### 1. react.py - ReAct 核心实现

#### 文件功能
定义 LLM 模型和工具集合，是 ReAct agent 的核心组件。

#### 代码拆解

```python
from dotenv import load_dotenv
from langchain_core.tools import tool
from langchain_openai.chat_models import ChatOpenAI
from langchain_tavily import TavilySearch

load_dotenv()
```

**导入说明**：
- `load_dotenv`: 加载环境变量
- `tool`: LangChain 工具装饰器
- `ChatOpenAI`: OpenAI 聊天模型
- `TavilySearch`: Tavily 搜索工具

---

```python
@tool
def triple(num: float) -> float:
    """
    :param num: a number to triple
    :return: the number tripled ->  multiplied by 3
    """
    return 3 * float(num)
```

**自定义工具**：
- **功能**：将数字乘以 3
- **装饰器**：`@tool` 将其转换为 LangChain 工具
- **用途**：演示如何创建自定义工具

**工具特点**：
- 有明确的输入输出类型
- 文档字符串用于 LLM 理解工具功能
- 可以被 LLM 自动调用

---

```python
tools = [TavilySearch(max_results=1), triple]
```

**工具列表**：
1. **TavilySearch(max_results=1)**
   - 网络搜索工具
   - `max_results=1`: 最多返回 1 个结果
   - 用于获取实时信息

2. **triple**
   - 自定义计算工具
   - 用于数学运算

---

```python
llm = ChatOpenAI(model="gpt-4o-mini").bind_tools(tools)
```

**LLM 配置**：
- **模型**：`gpt-4o-mini`（OpenAI 的轻量级模型）
- **`.bind_tools(tools)`**：
  - 将工具绑定到 LLM
  - LLM 可以决定何时调用哪个工具
  - 自动生成工具调用的格式

**工作原理**：
- LLM 会分析用户问题
- 如果需要工具，生成 `tool_calls`
- 否则直接返回文本回答

### 2. nodes.py - 节点实现

#### 文件功能
定义工作流中的节点，包括推理引擎和工具执行节点。

#### 代码拆解

```python
from dotenv import load_dotenv
from langgraph.graph import MessagesState
from langgraph.prebuilt import ToolNode
from react import llm, tools

load_dotenv()
```

**导入说明**：
- `MessagesState`: LangGraph 的消息状态类型
- `ToolNode`: LangGraph 预构建的工具执行节点
- `llm, tools`: 从 react.py 导入

---

```python
SYSTEM_MESSAGE = """
You are a helpful assistant that can use tools to answer questions.
"""
```

**系统提示词**：
- 定义 agent 的角色和行为
- 告诉 LLM 可以使用工具回答问题
- 简洁明了，让 LLM 自主决定工具使用

---

```python
def run_agent_reasoning_engine(state: MessagesState) -> MessagesState:
    response = llm.invoke(
        [{"role": "system", "content": SYSTEM_MESSAGE}, *state["messages"]]
    )
    return {"messages": [response]}
```

**推理引擎节点**：

**功能**：
- 这是 ReAct 中的"推理"（Reasoning）部分
- LLM 分析当前状态，决定下一步行动

**执行流程**：
1. **构建消息列表**：
   ```python
   [
       {"role": "system", "content": SYSTEM_MESSAGE},  # 系统消息
       *state["messages"]                              # 历史消息
   ]
   ```

2. **调用 LLM**：
   - LLM 分析对话历史
   - 决定是否需要调用工具
   - 如果需要，生成 `tool_calls`
   - 如果不需要，直接回答

3. **返回响应**：
   - 将 LLM 响应添加到消息列表
   - LangGraph 会自动更新状态

**可能的输出**：
- **文本回答**：`{"content": "答案是..."}`
- **工具调用**：`{"tool_calls": [{"name": "tavily_search", "args": {...}}]}`

---

```python
tool_node = ToolNode(tools)
```

**工具执行节点**：

**`ToolNode`**：
- LangGraph 预构建的节点
- 自动执行 LLM 请求的工具调用
- 将工具结果添加到消息列表

**工作原理**：
1. 从消息中提取 `tool_calls`
2. 找到对应的工具
3. 执行工具（传入参数）
4. 将结果包装成消息返回

**示例**：
```python
# LLM 生成
tool_calls = [{"name": "triple", "args": {"num": 5}}]

# ToolNode 执行
result = triple(num=5)  # 15

# 返回消息
{"role": "tool", "content": "15", "tool_call_id": "..."}
```

### 3. main.py - 工作流定义

#### 文件功能
定义完整的 LangGraph 工作流，连接所有节点。

#### 代码拆解

```python
from dotenv import load_dotenv
load_dotenv()

from langchain_core.messages import HumanMessage
from langgraph.graph import END, MessagesState, StateGraph
from nodes import run_agent_reasoning_engine, tool_node

AGENT_REASON = "agent_reason"
ACT = "act"
LAST = -1
```

**常量定义**：
- `AGENT_REASON`: 推理节点名称
- `ACT`: 工具执行节点名称
- `LAST`: 用于访问消息列表最后一个元素

---

```python
def should_continue(state: dict) -> str:
    if not state["messages"][LAST].tool_calls:
        return END
    return ACT
```

**条件判断函数**：

**功能**：
- 决定工作流的下一步
- 检查最后一条消息是否有工具调用

**逻辑**：
- **没有工具调用** → 返回 `END`（结束）
  - LLM 已经给出最终答案
- **有工具调用** → 返回 `ACT`（执行工具）
  - 需要先执行工具，再继续推理

**示例**：
```python
# 情况1：LLM 直接回答
messages = [HumanMessage("..."), AIMessage("答案是 42")]
# tool_calls = None
# → 返回 END

# 情况2：LLM 请求工具
messages = [HumanMessage("..."), AIMessage("...", tool_calls=[...])]
# tool_calls = [...]
# → 返回 ACT
```

---

```python
flow = StateGraph(MessagesState)
```

**创建状态图**：
- `StateGraph`: LangGraph 的状态图类
- `MessagesState`: 使用消息状态（标准对话状态）

**MessagesState 特点**：
- 自动管理消息列表
- 支持追加新消息
- 包含对话历史

---

```python
flow.add_node(AGENT_REASON, run_agent_reasoning_engine)
flow.set_entry_point(AGENT_REASON)
flow.add_node(ACT, tool_node)
```

**添加节点**：
1. **`add_node(AGENT_REASON, ...)`**
   - 添加推理节点
   - 节点函数：`run_agent_reasoning_engine`

2. **`set_entry_point(AGENT_REASON)`**
   - 设置入口点
   - 工作流从推理节点开始

3. **`add_node(ACT, tool_node)`**
   - 添加工具执行节点
   - 使用预构建的 `ToolNode`

---

```python
flow.add_conditional_edges(
    AGENT_REASON,
    should_continue,
    {
        END: END,
        ACT: ACT,
    },
)
```

**添加条件边**：

**功能**：
- 从 `AGENT_REASON` 节点出发
- 根据 `should_continue` 的结果决定下一步

**路由映射**：
- `END` → 结束工作流
- `ACT` → 执行工具节点

**执行流程**：
```
AGENT_REASON (推理)
    ↓
should_continue() 判断
    ├─→ END (结束)
    └─→ ACT (执行工具)
```

---

```python
flow.add_edge(ACT, AGENT_REASON)
```

**添加边**：
- 从 `ACT` 到 `AGENT_REASON`
- 工具执行完成后，继续推理

**为什么需要这个边？**
- 工具执行后，需要将结果反馈给 LLM
- LLM 基于工具结果继续推理
- 形成 ReAct 循环

---

```python
app = flow.compile()
app.get_graph().draw_mermaid_png(output_file_path="graph.png")
```

**编译和应用**：
1. **`compile()`**: 编译工作流图
2. **`draw_mermaid_png()`**: 生成可视化图

**生成的工作流图**：
```
开始 → agent_reason → [判断]
                        ├─→ END (结束)
                        └─→ ACT → agent_reason (循环)
```

---

```python
if __name__ == "__main__":
    print("Hello ReAct with LangGraph")
    res = app.invoke(
        {
            "messages": [
                HumanMessage(
                    content="what is the weather in sf? List it and then Triple it "
                )
            ]
        }
    )
    print(res["messages"][LAST].content)
```

**主程序执行**：

**输入**：
```python
{
    "messages": [
        HumanMessage("what is the weather in sf? List it and then Triple it")
    ]
}
```

**执行流程**：
1. **推理**：LLM 分析问题
   - 需要搜索天气信息
   - 需要将结果乘以 3

2. **执行工具1**：调用 `TavilySearch`
   - 搜索 "weather in sf"
   - 返回：例如 "72°F"

3. **推理**：LLM 看到工具结果
   - 需要调用 `triple` 工具

4. **执行工具2**：调用 `triple`
   - 输入：72
   - 返回：216

5. **推理**：LLM 整合结果
   - 生成最终答案

6. **结束**：返回最终消息

**输出**：
```python
res["messages"][-1].content
# "旧金山天气是 72°F，乘以 3 后是 216"
```

## 🔄 完整工作流程

### ReAct 循环

```
1. 推理 (Reasoning)
   ↓
   LLM 分析问题，决定行动
   ↓
2. 行动 (Acting)
   ↓
   执行工具（如果需要）
   ↓
3. 观察 (Observation)
   ↓
   获取工具结果
   ↓
4. 推理 (Reasoning)
   ↓
   基于结果继续推理
   ↓
   [循环直到完成]
```

### 实际执行示例

**问题**：`"what is the weather in sf? List it and then Triple it"`

**执行步骤**：

```
步骤1: agent_reason
  LLM: "我需要搜索旧金山天气"
  → tool_calls: [TavilySearch("weather in sf")]

步骤2: ACT
  执行: TavilySearch
  结果: "72°F"

步骤3: agent_reason
  LLM: "天气是 72°F，现在需要乘以 3"
  → tool_calls: [triple(72)]

步骤4: ACT
  执行: triple(72)
  结果: 216

步骤5: agent_reason
  LLM: "旧金山天气是 72°F，乘以 3 后是 216"
  → 无 tool_calls
  → END
```

## 🎯 关键设计模式

### 1. ReAct 模式
- **推理**：LLM 思考下一步行动
- **行动**：执行工具获取信息
- **循环**：直到完成任务

### 2. 图工作流
- **节点**：推理引擎、工具执行
- **边**：定义执行顺序
- **条件边**：根据状态决定路径

### 3. 状态管理
- **MessagesState**：自动管理对话历史
- **消息追加**：每次执行都添加新消息
- **工具调用跟踪**：自动关联工具调用和结果
