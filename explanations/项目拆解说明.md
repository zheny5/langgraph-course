# LangGraph Reflection Agent 项目完整拆解

## 📚 项目概述

这是一个基于 **LangGraph** 实现的 **Reflection（反思）Agent**，通过自我评估和迭代改进来提高输出质量。本项目实现了一个 **Twitter 推文改进助手**，通过多轮反思和修订来优化推文内容。

### 核心特点
- ✅ **Reflection 模式**：生成 → 反思 → 改进的循环
- ✅ **自我评估**：LLM 评估自己生成的内容
- ✅ **迭代改进**：基于反馈不断优化输出
- ✅ **质量保证**：多层检查机制

#### 代码拆解

#### 第一部分：导入和状态定义

```python
from typing import TypedDict, Annotated
from dotenv import load_dotenv
load_dotenv()

from langchain_core.messages import BaseMessage, HumanMessage
from langgraph.graph import END, StateGraph
from langgraph.graph.message import add_messages
```

**关键导入**：
- `TypedDict`: 类型字典
- `Annotated`: 类型注解
- `add_messages`: LangGraph 的消息合并函数

---

#### 状态定义

```python
class MessageGraph(TypedDict):
    messages: Annotated[list[BaseMessage], add_messages]
```

**状态结构**：
- `MessageGraph`: 图状态类型
- `messages`: 消息列表
- `Annotated`: 类型注解，指定合并函数

**`add_messages` 的作用**：
- LangGraph 的预定义合并函数
- 自动将新消息追加到消息列表
- 支持消息的增量更新

**等价写法**：
```python
# 使用 add_messages（推荐）
messages: Annotated[list[BaseMessage], add_messages]

# 手动实现（等价）
def add_messages(left: list[BaseMessage], right: list[BaseMessage]):
    return left + right
```

---

#### 节点定义

```python
REFLECT = "reflect"
GENERATE = "generate"
```

**常量定义**：
- `REFLECT`: 反思节点名称
- `GENERATE`: 生成节点名称

---

#### 生成节点（generation_node）

```python
def generation_node(state: MessageGraph):
    return {"messages": [generate_chain.invoke({"messages": state["messages"]})]}
```

**功能**：
- 调用生成链创建推文
- 将生成的消息添加到状态中

**执行流程**：
1. 从状态中提取消息列表
2. 调用 `generate_chain.invoke()`
3. 传入消息列表
4. 返回生成的消息

**返回格式**：
- 返回字典，包含新消息
- `add_messages` 会自动合并到状态中

---

#### 反思节点（reflection_node）

```python
def reflection_node(state: MessageGraph):
    res = reflect_chain.invoke({"messages": state["messages"]})
    return {"messages": [HumanMessage(content=res.content)]}
```

**功能**：
- 调用反思链评估推文
- 将反思结果作为用户消息添加

**执行流程**：
1. 从状态中提取消息列表
2. 调用 `reflect_chain.invoke()`
3. 获取反思结果
4. 将结果包装成 `HumanMessage`
5. 返回新消息

**为什么包装成 HumanMessage？**
- 让生成节点将反思当作用户反馈
- 触发生成节点的"修订模式"
- 实现反馈循环

---

#### 构建图

```python
builder = StateGraph(state_schema=MessageGraph)
builder.add_node(GENERATE, generation_node)
builder.add_node(REFLECT, reflection_node)
builder.set_entry_point(GENERATE)
```

**步骤**：
1. 创建状态图：`StateGraph(state_schema=MessageGraph)`
2. 添加生成节点
3. 添加反思节点
4. 设置入口点：从生成节点开始

---

#### 条件判断函数

```python
def should_continue(state: MessageGraph):
    if len(state["messages"]) > 6:
        return END
    return REFLECT
```

**功能**：
- 决定是否继续循环
- 检查消息数量

**逻辑**：
- **消息数 > 6** → 返回 `END`（结束）
- **消息数 ≤ 6** → 返回 `REFLECT`（继续反思）

**为什么是 6？**
- 防止无限循环
- 通常 3 轮改进就足够了（用户消息 + 生成 + 反思 + 生成 + 反思 + 生成 = 6 条消息）

---

#### 添加边

```python
builder.add_conditional_edges(GENERATE, should_continue)
builder.add_edge(REFLECT, GENERATE)
```

**条件边**：
- 从 `GENERATE` 出发
- 根据 `should_continue` 的结果路由
- 如果返回 `END` → 结束
- 如果返回 `REFLECT` → 执行反思节点

**普通边**：
- 从 `REFLECT` 到 `GENERATE`
- 反思后总是继续生成

---

#### 编译和可视化

```python
graph = builder.compile()
print(graph.get_graph().draw_mermaid())
graph.get_graph().print_ascii()
```

**功能**：
- `compile()`: 编译图
- `draw_mermaid()`: 生成 Mermaid 图
- `print_ascii()`: 打印 ASCII 图

## 🎯 关键设计模式

### 1. Reflection 模式
- **生成**：创建初始内容
- **反思**：评估质量，提供反馈
- **改进**：基于反馈重新生成
- **循环**：直到满意或达到上限

### 2. 状态管理
- **TypedDict**：类型安全的状态定义
- **Annotated**：指定合并函数
- **add_messages**：自动消息合并

### 3. 条件路由
- **should_continue**：根据消息数量决定是否继续
- **防止无限循环**：设置最大迭代次数
