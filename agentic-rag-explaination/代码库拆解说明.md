# LangGraph Course 代码库拆解说明

## 📚 项目概述

这是一个基于 **LangGraph** 实现的 **Agentic RAG（智能检索增强生成）** 系统。该系统能够智能地决定何时使用本地向量数据库检索，何时使用网络搜索，并具备自我评估和反馈机制。

## 🏗️ 项目结构

```
langgraph-course/
├── main.py                 # 主入口文件
├── ingestion.py            # 数据摄取和向量数据库初始化
├── graph/                  # 核心图结构模块
│   ├── graph.py           # LangGraph 工作流定义
│   ├── state.py           # 状态定义（TypedDict）
│   ├── consts.py          # 常量定义
│   ├── nodes/             # 图节点实现

│   │   ├── grade_documents.py    # 文档评分节点
│   │   ├── generate.py           # 生成节点
│   │   └── web_search.py         # 网络搜索节点
│   └── chains/            # LangChain 链定义
│       ├── router.py              # 路由链（决定使用向量库还是网络搜索）
│       ├── retrieval_grader.py    # 检索评分链
│       ├── generation.py          # 生成链
│       ├── answer_grader.py       # 答案评分链
│       └── hallucination_grader.py # 幻觉检测链
```

## 🔄 核心工作流程

### 1. 入口点（main.py）

```python
# 加载环境变量
load_dotenv()

# 从 graph.graph 导入编译好的应用
from graph.graph import app

# 执行查询
app.invoke(input={"question": "agent memory?"})
```

### 2. 状态定义（graph/state.py）

系统使用 `GraphState` TypedDict 来管理整个工作流的状态：

```python
class GraphState(TypedDict):
    question: str        # 用户问题
    generation: str      # LLM 生成的答案
    web_search: bool    # 是否需要网络搜索
    documents: List[str] # 检索到的文档列表
```

### 3. 工作流图（graph/graph.py）

工作流包含以下节点和决策点：

#### 节点类型：
- **RETRIEVE**: 从向量数据库检索相关文档
- **GRADE_DOCUMENTS**: 评估检索到的文档相关性
- **GENERATE**: 基于文档生成答案
- **WEBSEARCH**: 执行网络搜索

#### 工作流程：

```
开始
  ↓
[路由决策] → 判断问题类型
  ├─→ [WEBSEARCH] → 网络搜索 → [GENERATE] → 生成答案
  └─→ [RETRIEVE] → 检索文档
        ↓
    [GRADE_DOCUMENTS] → 评估文档相关性
        ├─→ 文档不相关 → [WEBSEARCH] → 网络搜索 → [GENERATE]
        └─→ 文档相关 → [GENERATE] → 生成答案
              ↓
          [评估生成结果]
              ├─→ 有幻觉 → 重新生成
              ├─→ 不回答问题 → [WEBSEARCH] → 重新生成
              └─→ 答案可用 → 结束
```

## 📦 核心模块详解

### 1. 数据摄取（ingestion.py）

**功能**：从网页加载文档，进行分块，并存储到 Chroma 向量数据库

**关键步骤**：
1. 使用 `WebBaseLoader` 从指定 URL 加载文档
2. 使用 `RecursiveCharacterTextSplitter` 进行文档分块
3. 使用 `HuggingFaceEmbeddings` 生成嵌入向量
4. 存储到 Chroma 向量数据库

**注意**：代码中使用了 HuggingFace 的嵌入模型而非 OpenAI，降低了成本。

### 2. 路由链（graph/chains/router.py）

**功能**：智能判断用户问题应该使用向量数据库还是网络搜索

**实现**：
- 使用结构化输出（`with_structured_output`）让 LLM 返回路由决策
- 如果问题涉及 agents、prompt engineering、adversarial attacks → 使用向量库
- 其他问题 → 使用网络搜索

### 3. 检索节点（graph/nodes/retrieve.py）

**功能**：从向量数据库检索与问题相关的文档

**实现**：
```python
def retrieve(state: GraphState) -> Dict[str, Any]:
    question = state["question"]
    documents = retriever.invoke(question)
    return {"documents": documents, "question": question}
```

### 4. 文档评分节点（graph/nodes/grade_documents.py）

**功能**：评估检索到的文档是否与问题相关

**逻辑**：
- 对每个文档进行相关性评分
- 如果文档不相关，设置 `web_search = True`
- 只保留相关文档

### 5. 网络搜索节点（graph/nodes/web_search.py）

**功能**：使用 Tavily API 进行网络搜索

**实现**：
- 使用 `TavilySearch` 工具执行搜索
- 将搜索结果转换为 Document 对象
- 合并到现有文档列表中

### 6. 生成节点（graph/nodes/generate.py）

**功能**：基于检索到的文档和问题生成答案

**实现**：
- 使用 LangSmith Hub 上的 RAG prompt 模板
- 将上下文和问题传递给 LLM
- 返回生成的答案

### 7. 幻觉检测链（graph/chains/hallucination_grader.py）

**功能**：检查生成的答案是否基于提供的文档

**评估标准**：
- `yes`: 答案基于文档中的事实
- `no`: 答案包含不在文档中的信息（幻觉）

### 8. 答案评分链（graph/chains/answer_grader.py）

**功能**：评估生成的答案是否真正回答了用户的问题

**评估标准**：
- `yes`: 答案解决了问题
- `no`: 答案没有解决问题

## 🔧 技术栈

- **LangGraph**: 图工作流框架
- **LangChain**: LLM 应用开发框架
- **Chroma**: 向量数据库
- **Tavily**: 网络搜索 API
- **HuggingFace**: 嵌入模型（sentence-transformers）
- **DeepSeek**: LLM 模型（替代 OpenAI）
- **Pydantic**: 数据验证和结构化输出

## ⚠️ USER_AGENT 错误说明

### 错误信息
```
USER_AGENT environment variable not set, consider setting it to identify your requests.
```

### 错误原因

这个警告/错误通常出现在使用 `WebBaseLoader` 或其他进行 HTTP 请求的库时。`USER_AGENT` 是 HTTP 请求头中的一个字段，用于标识发起请求的客户端类型。

**为什么需要 USER_AGENT？**
1. **服务器识别**：许多网站会根据 User-Agent 来决定是否允许访问
2. **反爬虫机制**：没有 User-Agent 的请求可能被识别为爬虫并被拒绝
3. **最佳实践**：设置 User-Agent 是网络请求的标准做法

### 解决方法

#### 方法 1：在代码中设置环境变量

在 `ingestion.py` 文件开头添加：

```python
import os
os.environ['USER_AGENT'] = 'Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/120.0.0.0 Safari/537.36'
```

#### 方法 2：在 .env 文件中设置

在项目的 `.env` 文件中添加：

```bash
USER_AGENT=Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/120.0.0.0 Safari/537.36
```

由于代码中已经使用了 `load_dotenv()`，环境变量会自动加载。

#### 方法 3：在 WebBaseLoader 中直接设置

修改 `ingestion.py` 中的 WebBaseLoader 调用：

```python
from langchain_community.document_loaders import WebBaseLoader

# 设置请求头
loader = WebBaseLoader(
    url,
    requests_kwargs={"headers": {"User-Agent": "Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36"}}
)
docs = loader.load()
```

### 推荐的 User-Agent 字符串

```python
# Chrome 浏览器
USER_AGENT = "Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/120.0.0.0 Safari/537.36"

# Firefox 浏览器
USER_AGENT = "Mozilla/5.0 (Windows NT 10.0; Win64; x64; rv:121.0) Gecko/20100101 Firefox/121.0"

# 自定义应用标识
USER_AGENT = "LangGraph-RAG-Bot/1.0 (Educational Purpose)"
```

## 📊 系统特点

1. **自适应检索**：根据问题类型自动选择检索方式
2. **质量保证**：多层评估机制（文档相关性、幻觉检测、答案质量）
3. **自我修正**：如果生成结果不理想，自动触发网络搜索或重新生成
4. **生产就绪**：代码结构清晰，易于维护和扩展

## 🔍 关键设计模式

1. **状态管理**：使用 TypedDict 确保类型安全
2. **条件路由**：使用 `add_conditional_edges` 实现智能决策
3. **链式组合**：使用 LangChain 的管道操作符 `|` 组合组件
4. **结构化输出**：使用 Pydantic 模型确保 LLM 输出格式正确

## 📝 总结

这是一个完整的 Agentic RAG 系统实现，展示了如何使用 LangGraph 构建复杂的、具有决策能力的 RAG 应用。系统通过多层评估和自适应检索，能够提供更准确、更可靠的答案。
